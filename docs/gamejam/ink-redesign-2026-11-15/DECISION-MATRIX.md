# Ink redesign · competing mechanisms and selection record

[Review](README.md) · [Market plan](MARKET-PLAN.md) · [Observation template](OBSERVATION-TEMPLATE.md)

**All eight directions are untested hypotheses. No favorite or implementation is selected.** These are alternatives for comparison, not eight features for one game. The shared foundation is authored ink, material response and recoverable originals.

| Family | Dominant player action and proposed goal | Why ink matters | Experiment that could reject it |
|---|---|---|---|
| Material experimentation | Draw, dilute, erase and combine marks to discover repeatable reactions | Width, contact and persistence change the material response | Change one property; reject or revise if outcomes stay arbitrary or cannot inform a second attempt |
| Construction and motion | Draw structures, run them and repair failures to transport something | Stroke geometry becomes usable terrain or support | Offer several repairs; reject if fine drawing precision dominates understanding |
| Living page ecology | Build habitats and channels; sustain a changing miniature ecosystem | Marks become habitat/flow, with lasting effects | Remove a component; reject if the result is passive decoration or needs continual explanation |
| Graphic programming | Connect repeatable operators and make the page perform an invented process | Spatial connections define executable rules | Transfer one learned rule to a new layout; reject if the system only selects hidden menu commands |
| Rhythm and choreography | Make, repeat and vary stroke sequences in response to a pattern | Timing and continuity become performance | Compare guided repetition with improvisation; reject if the reward depends on handwriting speed or unreliable latency |
| Restoration and investigation | Recover layers and remove interference to reconstruct how a page changed | Recoverable material history provides evidence | Allow multiple reconstructions; reject if the activity becomes hotspot hunting followed by a selected answer |
| Learning companion | Develop a shared mark vocabulary to accomplish a concrete task together | The player authors communication and revises misunderstandings | Try an unconventional solution; reject if hidden keywords or arbitrary interpretation determine success |
| Ink workshop/economy | Transform and reuse ink to make lasting creations through tradeoffs | Ink is both authored material and a resource | Remove score/currency displays; reject if the remaining action is repetitive clicking without an engaging task |

All proposed simulation, recognition, creature, program, rhythm and economy rules would require new work. The original product’s OCR-to-text reply path does not implement them. A concept involving semantic handwriting must specify recognition coverage and recovery; a geometric concept must explain why its input remains meaningful without a stylus.

## Comparison criteria

For each family, enter **supported / challenged / unresolved**, followed by an observation ID and its exact scope. Do not assign numerical confidence to missing evidence or total these criteria into a pseudo-precise ranking.

| Criterion | Evidence sought |
|---|---|
| Ink is essential | Altering a mark changes a consequential outcome, not merely its appearance |
| Agency is understandable | A player can form a prediction, observe a result and use it to revise an action |
| Continued play has a reason | Voluntary variation, a new self-chosen question, mastery or attachment; prompted compliance is separate |
| Recovery invites experimentation | A mistake has a legible, proportionate cost and a discoverable repair |
| Expression survives constraints | More than one viable approach or meaningful authored variation |
| Story fits the activity | Objects, actions and changes can carry narrative; characters/stories remain replaceable |
| Input and language are feasible | Mouse, finger, stylus and keyboard strategy; en/ja/zh-Hans; pressure and English OCR are not universal assumptions |
| A browser release is supportable | Entry time, memory, performance, save semantics, provider/offline requirements and content cost have an explicit plan |
