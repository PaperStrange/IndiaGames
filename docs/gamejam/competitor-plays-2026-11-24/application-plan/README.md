# Application plan — competitor learnings applied to the four own games

**Status:** proposals, 2026-11-25. Each PRD is a hypothesis with a falsifiable gate and a terminal kill criterion. Nothing here is a solution until its gate passes.

## The filter

Every application must change a decision, not just the wording or gesture — the governing thesis from the synthesis (`docs/competitor-learning-2026-11-25/SYNTHESIS.md`). Anything that only rewords, redecorates, or adds a badge fails the filter.

## Order (the synthesis's sequence)

1. **Notebook** — comparisons and the eight-family matrix first (step 1). The three ink experiments are selected only after TN-12 completes and the matrix is populated.
2. **Vivid** — the bounded comparison, one intervention (step 4).
3. **Small Hours** — the game agent, gated on the six-pair human test (step 5).
4. **Bell** — the game agent, Contrast mode first (step 5).

## How to read a PRD

Each PRD follows Lenny's shape: Description, Problem, Why now, Success, Audience, What. What and why only — no technical how (that is the RFC), no sprint plan (that is the dev plan). Hypotheses are written as "The team believes…" with a falsifiable gate and a terminal kill criterion, each traced to its evidence with an evidence label ([REAL] / [SECONDARY] / [OPEN]). A killed hypothesis is a result, not a failure.

## What is not in this plan

- No technical how. No sprint plan. No build. The dev plan is a separate document, written only after the PRDs are approved.
- No claim that the keepsake is unique. Its differentiator is unproven (Gartic's shareable album is the nearest rival artifact) and the Small Hours PRD tests it rather than asserting it.
- No validation by agent play. Every hypothesis is written for a human gate. More agent play cannot validate these applications.
