# Observation templates and how to use them

**Updated 6 October 2026. These templates are blank; they contain no new play results.** The [research plan](research-plan-2026-10-06.md) remains pending agreement before execution.

| Template | Use | Output |
|---|---|---|
| [Player journey](journey-observation-template.md) | One per exact game edition, with separate sessions and locked first-pass notes | Entry-to-exit route, intentions/actions/consequences, recovery, ending or explicit stopping point, and actual re-entry if observed |
| [Art and sensory journey](art-observation-template.md) | Alongside each journey | Annotated evidence board, clue/feedback sequences, style/mechanic analysis and verified audio coverage |
| [Competitor coverage](competitor-coverage-template.md) | One per playable demo | At least six distinct studied competitors across at least four broad play families, with access gaps and completion labels |
| [Concept decision brief](concept-decision-template.md) | One per playable demo after the coverage audit | Answers to motivation, platform differentiation and distinctive experience, linked to evidence and contrary examples |

Start with the [per-demo competitor matrix](competitor-matrix-2026-10-06.md), retaining each assignment ID in observations. Use one canonical journey for a shared title; add distinct questions and any further analytical pass for each demo. A shared title contributes once to the unique-game total and once to each relevant demo's covered list. Replaying it does not add another competitor.

Blank fields remain unknown. Store text, critic accounts, agent observations and actual human reports retain separate labels. Do not fill missing endings, reactions or access checks from expectation.
