# MC-029 — Choose a conversation rhythm that respects my writing

Type: Story. Priority: P1. Status: Proposed, next-sprint refinement. Owner roles: Client + Product + QA; people unassigned. Estimate: unestimated. Dependencies: MC-006, MC-021. Related: MC-012, MC-028, MC-030.

As a writer moving between desktop, iPad and phone, I want the notebook to respect my input method and chosen conversation style, so that thinking pauses remain comfortable and I control when a reply starts.

## Acceptance criteria

- [ ] Composer text always uses Enter/Send; IME Enter does not submit. Surface pause timing changes only through the selected policy and remains visibly configurable.
- [ ] Mouse, Pencil/pen, touch and keyboard changes are handled within the same session. Unknown input defaults to explicit submission. No psychological category is inferred from hardware or private writing.
- [ ] Conversation, Research, Reflection, Supportive reflection and Roleplay follow the linked sprint specification. Manual override persists for the chosen scope and is reversible.
- [ ] Input end begins recognition and the five-second fade at one timestamp. Erasure, rewrite, page changes, dialogs and overlapping recognition preserve MC-006 invariants.
- [ ] A failed request preserves the original input and draft. A background result cannot occupy a newly selected turn. Exactly one submitted turn is created per accepted input end.
- [ ] At least 30 actual journeys per input method include deliberate pauses, corrections, composition and navigation. Report unintended submissions and task completion by profile; acceptance requires zero unintended submissions in this finite set.

## Implementation and evidence

Create a typed policy model and one explicit turn state machine. Keep timing decisions local; record policy ID, input method, revision and timestamps without raw text. Wire profile selection, Keep writing and Respond controls. Evaluate the proposed timings with observed pauses; any changed target is agreed before acceptance runs.
