## Proposed engineering sequence

These are proposals for the next settled implementation plan, not work marked started or complete.

| Work item | Agent deliverable and acceptance | Human contribution |
|---|---|---|
| **B-L1 · Separate game semantics from English** | Give every action, person, bond, object, scar, forecast option and journal event a stable ID. Replace label-prefix cost/branch checks with explicit metadata. Preserve existing English outcome/cost traces; no label or translated punctuation may change eligibility, Momentum, Fracture, phase, duplicate-reward guards or victory. Keep immutable Original/reference artifacts outside the refactor. | Designer reviews the equivalence ledger and ambiguous legacy branches before translation. |
| **B-L2 · Author and validate three locale catalogs** | Extract all player-facing surfaces, including HTML/ARIA/CSS labels and rendered history; use parameterized messages rather than English sentence concatenation. Declare supported `en`, `ja`, `zh-Hans`, explicit selection and fallback behavior, correct document `lang`, missing-key/placeholder validation and stable option order/answer identity. Recommended study rule: lock the preregistered locale for a run. Public in-run switching, if selected, must re-render without spending an action or resetting the run. | Fluent Japanese and Simplified Chinese reviewers approve glossary, names, register, clue ambiguity, “witnessed/reported/interrupted,” costs and neutral facilitator prompts. Translation tools can draft; they cannot supply this approval. |
| **B-L3 · Localize art and make text robust** | Choose the map lettering strategy; retain equivalent accessible place/phase labels and landmarks. Specify available CJK font coverage/fallback and licenses if fonts are shipped. Check real translated text plus expansion fixtures at phone/tablet/desktop sizes, enlarged text and zoom. No clipped action/cost/receipt controls, lost labels or reliance on color/hover; verify focus, dialogs, live announcements and reduced motion. | Native-language visual review and actual screen-reader/device use. Physical legibility is not established by a screenshot. |
| **B-D1 · Extend the reproducible compatibility suite** | After the plan is settled, run core state scenarios in Chromium, Firefox and WebKit where available, with desktop/phone/tablet viewport and input configurations. Add rotation/resizing, browser history/reload, hidden/resumed page, modal recovery, split/nested/embedded artifact and offline-asset checks. Treat a WebKit automation pass as engine evidence, not an iPad/iPhone pass. Preserve the current build/negative tests and exact-byte result records. | Test actual advertised phone/tablet browser families: proposed iOS Safari, Android Chrome, iPadOS Safari and Android tablet Chrome; assign concrete models/OS/browser before claiming support. Include a desktop keyboard path and tablet touch + attached keyboard where claimed. |
| **B-R1 · Version the localized study/release handoff** | New bytes receive a new version and artifact inventory, locale catalog hashes and declared device/browser support. Create blank per-locale/device result rows, build/order/locale preregistration and links to previous artifacts. Retain failed/assisted attempts; do not pool mixed languages/builds into one comparison or reuse old exact-build approval automatically. | Research lead settles locale-specific study scope, facilitator/reviewer assignments and participant competency; independent human release reviewer plays the exact proposed artifact and judges original records. |

## Critical journey matrix for planning

All rows are **planned / not run for the multilingual scope**. A functional QA run can share the same tester across device checks; it does not become a fresh formative participant row.

| Journey | Language check | Device/input check | Invariant |
|---|---|---|---|
| Entry → choose locale → Contrast → forecast | Correct language, readable glossary, no accidental answer cue | Desktop keyboard; phone touch; tablet portrait/landscape; correct page/screen-reader language | Locale selection spends no action; forecasts lock at the same point |
| Witness blocked Mina crossing → midnight → next morning preparation | “Witnessed” differs from town report and late discovery; clue/action meaning survives translation | Scroll/map targets, readable ledger, scene and dialog focus | Only a witnessed blockage supplies the clue; no late retroactive eyewitness credit |
| Borrowed preparation → held bell → next real boundary | Clearly distinguish one Momentum from unchanged Fracture; translated receipt and journal agree | Tablet hybrid input and repeat taps; tiny/wide layouts | One spend, one eligible extra visit; forecast reward resolves once at the actual boundary |
| Fracture 4 before Noon / missed preparation | Interruption does not claim success; recovery instructions understandable | Background/resume, rotation during pending choice, disabled-control state | Catastrophe overrides the bell; no invented outcome, clue or reward |
| Ending, restart, reload, voluntary exit | Complete debrief and truthful reload-loss wording | Real phone browser lifecycle; desktop history; tablet process eviction | No promised persistence is invented; original/reference/candidate identities remain distinct |

## Evidence and study boundaries

The latest [TB-22 record](https://github.com/PaperStrange/IndiaGames/blob/b451f5dd90294b8713dfdf6518b5d43baf47e948/docs/gamejam/technical-freeze-2026-11-06/README.md#L5) reports 25 Node tests, 20 clean static checks, five inventory tests and matching frozen build bytes. It adds no browser or physical-device evidence. The [browser runner](https://github.com/PaperStrange/IndiaGames/blob/b451f5dd90294b8713dfdf6518b5d43baf47e948/tests/square-journey.cjs#L6) uses Chromium and labels mobile dimensions as emulation; [November 5 setup QA](https://github.com/PaperStrange/IndiaGames/blob/b451f5dd90294b8713dfdf6518b5d43baf47e948/docs/gamejam/readiness-2026-11-05/TECHNICAL-QA.md#L18) separately discloses the previous reference's optional-font failures. These are historical results, not this audit's new tests.

Keep the [existing preregistration](https://github.com/PaperStrange/IndiaGames/blob/b451f5dd90294b8713dfdf6518b5d43baf47e948/docs/gamejam/milestone-2026-10-27/protocol.md#L7): six fresh participants, three reference-first and three candidate-first, a 20-minute maximum per build, at least 120 seconds of neutral activity before recall, no solution cues, all attempts retained. Existing thresholds remain 4/6 cause-and-prediction, 4/6 unaided earned-action-and-Fracture explanation, and 3/6 specific-outcome recall. A native-language review or device QA pass cannot replace them.

Do not divide six participants into two per language and report each language as satisfying a six-person gate. Do not compare a Japanese candidate with an English reference and attribute differences solely to the game mechanic. If a localized comparison is selected, freeze a matched-language candidate/reference pair as separately versioned artifacts and preregister its cohort; preserve the old English reference unchanged. The research lead must settle the additional locale-specific human evidence before multilingual release claims. Device families named in the new scope exceed the existing minimum of one physical phone, so the old minimum does not establish support for all phones/tablets. [Manual checks](https://github.com/PaperStrange/IndiaGames/blob/b451f5dd90294b8713dfdf6518b5d43baf47e948/docs/gamejam/launch-2026-11-20/MANUAL-CHECKS.md#L13) remain blank and apply to exact artifacts.
