## User outcome

As a **person enabling a tool**, I want **understandable tool scope and controlled execution**, so that **plugins can help without accessing unrelated notebooks**.

## Why this work is needed

Generic adapters exist but real service conformance and outbound controls need validation.

## Acceptance criteria

- [ ] **AC1.** Given a newly discovered tool, when connected, then tools remain disabled until selected and scoped; invalid schemas or unsupported protocol fail clearly.
- [ ] **AC2.** Given a malicious tool result or disallowed destination, when execution is attempted, then it cannot widen scope, follow unsafe redirects or send unrelated note content.
- [ ] **AC3.** Given representative HTTP and MCP test services, when called, then timeout, auth, citations and supported artifacts are verified; failed tools do not fabricate results.

## Implementation outline

1. Enforce endpoint/DNS/redirect and payload boundaries.
2. Exercise two minimal conformance services.
3. Record permission/credential changes and result provenance.

## Scope and readiness

Implement this bounded outcome; preserve the accepted ink interaction and existing functionality.

**Readiness:** Approved test service endpoints needed. Full PaperReadingAgent research hosting is MC-025, not a prerequisite for every notebook turn.

## Required review artifacts

- Injection/egress cases

## Definition of done and evidence

Acceptance criteria pass on the candidate revision; changed behavior has meaningful tests and relevant UI checks; critical privacy/data-loss defects are closed. Record the source/deployment, test environment and limitations. A fixture does not count as a live provider test, and a mobile bundle does not count as physical-device evidence.
