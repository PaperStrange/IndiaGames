## User outcome

As a **privacy-conscious user**, I want **clear processing destinations and minimum necessary context**, so that **I can choose AI connections knowingly**.

## Why this work is needed

Complete data inventory, handling terms and operational review are open.

## Acceptance criteria

- [ ] **AC1.** Given a provider/tool selection, when enabled, then selected data categories, destination and retention terms are recorded and disclosed appropriately.
- [ ] **AC2.** Given a request and analytics event, when inspected, then only needed context is sent and raw notebook text/keys are excluded from routine logs.
- [ ] **AC3.** Given consent or connection revocation, when another request is attempted, then the revoked route cannot continue; research opt-in is separate from personal memory learning.

## Implementation outline

1. Map data flows and selected providers’ handling terms.
2. Implement minimal-context/redacted telemetry and revocation.
3. Review claims, including the absence of server-blind E2EE.

## Scope and readiness

Implement this bounded outcome; preserve the accepted ink interaction and existing functionality.

**Readiness:** Qualified privacy review and selected provider/market decisions are required.

## Required review artifacts

- Data inventory
- Destination/retention review
- Redaction and revocation tests

Acceptance criteria pass on the candidate revision; changed behavior has meaningful tests and relevant UI checks; critical privacy/data-loss defects are closed. Record the source/deployment, test environment and limitations. A fixture does not count as a live provider test, and a mobile bundle does not count as physical-device evidence.
