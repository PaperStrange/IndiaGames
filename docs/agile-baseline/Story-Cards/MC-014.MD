## User outcome

As a **multi-device writer**, I want **recoverable conflicts and retries**, so that **concurrent or interrupted work does not disappear**.

## Why this work is needed

Thin idempotent handoff does not prove the complete fault model.

## Acceptance criteria

- [ ] **AC1.** Given 100 specified interruption/sync/restart cases, when executed, then no acknowledged operation is lost within the declared failure model.
- [ ] **AC2.** Given concurrent non-mergeable edits, when reconciliation occurs, then both versions are available and a user resolution is versioned.
- [ ] **AC3.** Given offline deletion followed by reconnect or expired authentication, when processing resumes, then deleted records are not resurrected and unauthorized writes are rejected.

## Implementation outline

1. Expand operation/conflict semantics and migration tests.
2. Inject retries, disconnects, restart and clock differences.
3. Test resolution after account/session changes.
