## User outcome

As a **notebook owner**, I want **visible memory history, undo and explicit recall scope**, so that **the companion learns while I retain control**.

## Why this work is needed

Existing controls need end-to-end validation with source-version changes and real sessions.

## Acceptance criteria

- [ ] **AC1.** Given useful automatic learning, when a memory is saved, then its source, kind and history are visible and it can be edited, forgotten or restored.
- [ ] **AC2.** Given default scope, when answering in notebook A, then notebook B is excluded; explicit cross-notebook selection permits only authorized scope.
- [ ] **AC3.** Given a model or notebook change, when continuing, then the same companion identity/settings persist; instruction/tool-strategy proposals remain unapplied until reviewed.

## Implementation outline

1. Connect existing memory UI to revised records.
2. Verify scope and review/rollback controls.
3. Test identity continuity independent of provider IDs.
