## User outcome

As a **notebook owner**, I want **reliable acknowledgments when reconnecting**, so that **I can resume the same saved note on another client**.

## Why this work is needed

Snapshot conflicts reject overwrites but do not reconcile operations.

## Acceptance criteria

- [ ] **AC1.** Given a pending operation retried twice, when the server accepts it, then the result is idempotent and the client clears the queue only after a durable acknowledgment.
- [ ] **AC2.** Given a synced note, when a second authenticated client opens it, then content and revision match the acknowledged version.
- [ ] **AC3.** Given a conflicting base revision, when safe merge is unavailable, then both recoverable versions remain and the UI names the conflict rather than silently overwriting.

## Implementation outline

1. Implement operation commit/ack API against agreed contract.
2. Reconnect and retry with bounded error states.
3. Demonstrate two-client sequential handoff and one conflict.
