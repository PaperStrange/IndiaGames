## User outcome

As a **mobile and web writer**, I want **usable ink, input and recovery on my device**, so that **the experience works outside a desktop preview**.

## Why this work is needed

Shared bundle and iframe tests do not certify native sessions, stylus or accessibility.

## Acceptance criteria

- [ ] **AC1.** Given installed test builds on iPad/Pencil, iPhone, Android phone and stylus tablet, when critical write/correct/sync/reopen journeys run, then they pass with evidence.
- [ ] **AC2.** Given IME composition, palm contact, rotation, keyboard-only input, screen reader or reduced motion, when used, then input and essential controls remain usable without duplicate automatic sends.
- [ ] **AC3.** Given baseline performance traces, when reviewed, then p95 ink paint targets 50 ms on the declared device/workload; model/media cold starts and failures are recorded.

## Implementation outline

1. Prepare native test projects/auth flows and deployment route.
2. Run device/accessibility matrix with actual hardware.
3. Repair measured defects and document device limitations.

## Scope and readiness

Implement this bounded outcome; preserve the accepted ink interaction and existing functionality.

**Readiness:** Physical hardware, native test signing and session setup needed; app-store approval is later.

## Required review artifacts

- Device matrix and recordings
- IME/accessibility results
- Ink/turn/latency measurements

## Definition of done and evidence

Acceptance criteria pass on the candidate revision; changed behavior has meaningful tests and relevant UI checks; critical privacy/data-loss defects are closed. Record the source/deployment, test environment and limitations. A fixture does not count as a live provider test, and a mobile bundle does not count as physical-device evidence. See [the shared checklist](../03-READY-DONE-AND-QA.MD).
