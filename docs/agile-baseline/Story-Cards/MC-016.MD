## User outcome

As a **notebook owner**, I want **a usable export and reliable deletion**, so that **my data remains portable and under my control**.

## Why this work is needed

Current page export and memory forget are not complete account-data export/deletion.

## Acceptance criteria

- [ ] **AC1.** Given an authorized export, when opened independently, then notes, ink, attachments and memory provenance are understandable and another user’s content is absent.
- [ ] **AC2.** Given confirmed account/content deletion, when recall, sync and tool access run, then deleted material is inaccessible and old clients cannot restore it.
- [ ] **AC3.** Given retained immutable backups, when deletion is requested, then the documented expiry and restore-time tombstone policy is applied without claiming instant erasure everywhere.

## Implementation outline

1. Define portable versioned export format.
2. Implement deletion across objects, memories, indexes and sessions.
3. Verify export reading and deletion propagation.

## Scope and readiness

Implement this bounded outcome; preserve the accepted ink interaction and existing functionality.

**Readiness:** None identified beyond dependencies; refine before commitment.

- Deletion test record
